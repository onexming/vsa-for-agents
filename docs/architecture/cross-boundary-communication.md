# 跨边界协作规范

本文件用于设计或修改切片间、领域间及交付单元间的依赖。切片内部文件默认私有；每条跨边界依赖都必须通过稳定契约连接，并在组合根显式装配。

## 选择流程

1. **描绘依赖：** 写明生产方、消费方、协作目的、同步性、一致性、失败方式和契约所有者；每条边及其业务原因均已列出时完成。
2. **选择机制：** 为每条边确定一种主机制——共同技术依赖、领域事件或公开协议；机制与协作目的逐条匹配时完成。
3. **定义契约：** 明确输入、结果、错误、载荷、可观察结果、所有者和兼容性策略；调用方无需了解提供方内部对象或目录时完成。
4. **实现两侧：** 生产方与消费方只依赖契约，各自保留业务流程和私有适配；没有内部导入、重新导出或技术层业务转发时完成。
5. **显式装配：** 在组合根连接订阅、客户端和具体实现；装配不依赖全局状态或导入副作用，且不包含业务判断时完成。
6. **验证边界：** 从双方公共入口验证成功、主要失败、契约兼容性和可观察结果，并运行依赖检查；所有场景和每条依赖边均有证据时完成。

频繁同步读取且要求强一致时，先重新判断领域和交付单元边界，或评估本地投影与事件同步；源码导入不能替代错误服务边界的修正。

## 机制判定

| 主目的 | 机制 | 边界要求 |
|---|---|---|
| 多个切片使用同一无业务语义能力 | 共同依赖 `shared/` | 时钟、传输、日志等技术能力保持被动，不转发业务调用 |
| 一个行为完成后触发通知、审计、同步、索引或异步处理 | 领域事件或消息 | 生产者发布事实，独立消费切片订阅；双方不互相导入 |
| 同步查询其他领域，或调用其他交付单元 | 公开 API、RPC、请求消息或等价协议 | 调用方依赖公开响应契约或独立 Schema |

业务事实事件使用过去式语义，载荷只包含订阅者所需公开数据。契约由能力提供方或独立协议包维护。

## 公开契约

每份跨边界契约必须同时满足：

- 字段、错误和语义明确，并定义可观察结果。
- 所有者与兼容性策略明确；破坏公开 API 时按根 `AGENTS.md` 的授权闸门处理。
- 传递序列化数据或稳定值，不携带数据库连接、框架请求对象、界面组件等运行时内部对象。
- 调用方不需要提供方的内部模型、仓储、处理器、持久化方式或目录结构。

## 边界守卫

以下任一情况都说明稳定边界尚未建立：

- 调用方直接导入其他切片的处理器、内部模型、私有校验或仓储。
- `adapter`、`bridge`、`facade` 或 `proxy` 只重新导出内部实现，使调用方继续随提供方内部变化。
- 全局 `shared/` 承担业务转发或服务定位。
- 跨交付单元共享某服务的领域模型实现、处理器、仓储或事务流程。
- 注册依赖隐式全局状态或导入副作用。

修复时建立事件或公开协议；若双方总是同步变化，则重新划分意图或领域边界。

## 通知与跨交付单元

“发送订单确认”等业务通知是独立消费切片，通用邮件客户端才属于技术共享。跨交付单元只共享公开 Schema、接口描述、生成客户端所需契约及无业务语义技术库；每个交付单元保有自己的组合根和启动入口。

## 完成标准

每条跨边界依赖都有唯一目的、合适机制、公开契约、所有者、兼容性策略和显式组合关系；双方不接触彼此内部实现，成功与失败行为均已验证时，协作设计才完成。

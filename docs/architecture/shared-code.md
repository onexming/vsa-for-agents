# 共享代码规范

本文件用于创建、修改或审查切片私有代码、领域 `_shared/`、全局 `shared/`、公共模型、规则、查询和技术工具。

## 决策流程

1. **枚举调用方：** 列出当前全部真实调用切片及其使用语义；调用点无遗漏且能区分当前复用与未来猜测时完成。
2. **识别行为：** 检查候选是否拥有独立输入、失败分支、状态变化或其他可观察结果；若有，将其建模为切片或公开能力，目标行为所有者明确时完成。
3. **判断语义：** 判断内容是否含领域语言、是否产生业务副作用、是否编排用例；答案能唯一落入切片私有、领域共享或全局共享时完成。
4. **逐级放置：** 单切片使用保留私有，并允许切片间暂时存在小规模重复；同领域真实复用提升到 `_shared/`；跨领域且无业务语义时再提升到 `shared/`。一次最多提升一层，所有调用方与目标层级匹配时完成。
5. **收紧契约：** 使用清晰、单一职责的业务或技术名称；公开面只包含调用方共同需要的稳定部分，且没有 `utils`、`helpers`、`common` 等模糊容器时完成。
6. **保持被动：** 提取物不调用切片、不转发其他边界、不按场景标志编排多个用例；依赖方向只从行为指向共享定义时完成。
7. **迁移验证：** 逐个迁移调用方，保持其公共行为不变；原切片测试、共享契约测试和依赖检查全部通过，且没有循环依赖时完成。

修改现有共享模块也从第一步开始；调用方、语义或副作用发生变化时，重新决定层级，而不是默认保留当前位置。

## 层级判定

```text
切片私有  ──→  领域 _shared  ──→  全局 shared
单一行为需要    同领域真实复用      跨领域纯技术复用
```

| 层级 | 进入条件 | 典型内容 |
|---|---|---|
| `features/<domain>/<slice>/` | 一个切片使用，或内容构成主动行为 | 输入输出、错误分支、流程、状态变化、专属端口与适配器、映射、展示、副作用 |
| `features/<domain>/_shared/` | 同领域至少两个切片使用同一稳定概念，且模块被动 | 模型、值对象、契约、错误、事件、纯计算、纯判断、稳定查询 |
| `shared/` | 跨领域复用，移除领域名称后仍成立，且仅含技术语义 | 连接与事务、传输、安全、日志、指标、配置、时钟、标识符、调度、测试设施 |

领域 `_shared/` 可以抛出稳定领域错误，但不读写外部状态、不发消息、不调用网络，也不驱动任何切片。全局 `shared/` 不包含领域模型、业务状态机、业务错误、特定领域查询、业务 Repository 或跨领域流程，并且不依赖任何具体领域。

## 停止提取

出现以下任一信号时，停止共享提取，改为建立切片、公开协议或重新划分领域：

- 候选拥有独立校验、错误分支或可观察结果。
- 候选写状态、发消息、调用外部服务或掌握多个切片的内部状态。
- 调用方需要大量场景标志控制流程。
- `Service`、`Manager`、`Processor` 或 `Coordinator` 聚合多个意图。
- 修改候选要求多个无关领域同步变化。
- `_shared/` 持续增长或出现高扇入；此时读取 [`edge-cases.md`](edge-cases.md)。

## Repository、查询与相似代码

- 只服务一个切片的查询保留私有；同领域多个切片复用同一稳定领域查询时，才作为被动查询进入 `_shared/`。
- 同时实现创建、审批、取消等主动流程的 Repository 或 Service 按行为拆回切片。
- UUID、邮箱语法、编码等纯技术校验可以进入全局共享；含领域含义的相似规则由各领域拥有。
- 相似逻辑需要状态或副作用时，它是行为或公开能力。所有者仍不明确时读取 [`edge-cases.md`](edge-cases.md)。

## 完成标准

每个共享模块都有完整的真实调用方清单、唯一稳定职责、正确层级和公开契约验证；模块保持被动，调用方公共行为不变，依赖检查无违规或循环时，共享工作才完成。

# 共享代码规范

本文件是创建、修改或审查切片私有代码、领域 `_shared/`、全局 `shared/`、公共模型、规则、查询和技术工具时的权威流程。

## 就近与逐级提升

```text
切片私有  ──→  领域 _shared  ──→  全局 shared
单一行为需要    同领域真实复用      跨领域纯技术复用
```

代码首先属于具体切片。只被一个切片使用时，即使预期未来复用，也保持私有；允许切片之间暂时存在小规模重复。每次最多提升一层，不得从切片直接跳到全局共享。

## 三个层级

### 切片私有

位置：`features/<domain>/<slice>/`。

包括该行为独有的输入输出契约、错误分支、业务流程、状态变化、数据访问端口及适配器、映射、展示、序列化、事件处理、副作用和完整行为测试。

### 领域共享

位置：`features/<domain>/_shared/`。候选内容必须同时满足：

1. 已被同一领域至少两个切片实际使用。
2. 表达同一个稳定领域概念，而非仅有相似代码形状。
3. 是模型、值对象、契约、错误、事件、纯计算、纯判断或被动查询。
4. 不编排完整业务流程，不调用切片内部实现，不替其他领域转发能力。
5. 不通过读写外部状态、发消息或调用网络产生业务副作用。

纯领域函数可以抛出稳定领域错误；抛出错误不等于副作用。被多个切片复用的稳定领域查询可以进入 `_shared/`，但创建、审批、取消等主动行为必须留在各自切片。

### 全局共享

位置：`shared/`。只容纳移除领域名称后仍然成立的技术基础设施，例如持久化连接与事务、通用传输、安全、日志、指标、追踪、配置、时钟、标识符生成、调度和无业务语义的测试设施。

包含领域模型、业务状态机、业务错误、特定领域查询、业务 Repository 或跨领域流程的模块不得进入全局共享。全局共享模块也不得反向依赖任何具体领域。

## 提取流程

1. **证明复用：** 列出至少两个真实调用切片；调用点完整且属于相同概念时完成。
2. **判断语义：** 回答代码是否仍含领域语义、是否产生业务副作用、是否编排用例；答案能唯一决定目标层级时完成。
3. **提取稳定契约：** 使用清晰、单一职责的业务或技术名称，避免 `utils`、`helpers`、`common` 等模糊容器。
4. **保持被动：** 提取物不调用任何切片，不按标志位切换多个用例，不重新导出其他边界的内部实现。
5. **逐个迁移调用方：** 不改变各切片的公共行为；所有调用方和兼容性影响均已核对时完成。
6. **验证：** 原切片测试、共享契约测试和依赖检查通过；无循环依赖，且使用者无需理解调用切片内部流程。

## 停止提取的信号

出现任一情况时停止提取，改为新建切片、建立公开协议或重新划分领域：

- 候选逻辑拥有独立输入校验、错误分支或可观察结果。
- 它写数据库、发消息、调用外部服务或掌握多个切片的内部状态。
- 调用方必须传入大量场景标志控制流程。
- 模块以 `Service`、`Manager`、`Processor`、`Coordinator` 等泛化名称聚合多个意图。
- 修改它需要同步修改多个无关领域。
- `_shared/` 持续增长或被大量切片引用；此时还必须读取 [`edge-cases.md`](edge-cases.md)。

## Repository 与查询

相同数据访问代码不自动形成 Repository。只服务一个切片的查询保留在切片内；同领域多个切片复用且表达稳定领域查询时，可以作为被动查询进入 `_shared/`。同时包含多个行为流程的 Repository 或 Service 应拆回切片。

## 跨领域相似代码

纯格式或技术校验可进入全局共享；包含领域含义的规则由各领域独立拥有。若相似逻辑需要状态或副作用，它是行为或公开能力，不是共享函数。判断仍不明确时读取 [`edge-cases.md`](edge-cases.md)。

## 完成标准

每个共享模块都有至少两个真实调用方、唯一且稳定的职责、正确的层级和针对公开契约的验证；它不编排用例、不依赖切片内部、不产生领域副作用，也未引入循环依赖。

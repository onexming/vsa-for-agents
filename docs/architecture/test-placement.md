# 测试文件放置规范

本文件是测试文件及其配套环境文件位置的唯一权威来源。它只规定文件归属，不规定测试应覆盖什么行为、如何授权和执行真实环境测试，或者如何判定环境清理成功。

新增、修改、移动或审查测试文件前，先识别测试必须同时观察的最小公共边界，再按本文件放置。具体名称和测试源码集布局服从语言工具链；工具强制位置影响业务边界时，读取 [`exceptions.md`](exceptions.md)。

## 测试提升阶梯

```text
切片公共行为          → <source-root>/features/<domain>/<slice>/<test>.*
同领域跨切片业务场景  → <source-root>/features/<domain>/<test>.*
跨领域业务场景        → <source-root>/features/<test>.*
依赖真实环境的测试    → <repository>/real_tests/<capability-or-system>/
```

测试覆盖的业务边界越大，位置越接近相应生产代码的共同根。只有测试场景必须同时观察多个切片或领域的公共结果时才提升；导入多个模块、使用共享模块或测试替身、测试代码较长，都不构成提升理由。

同领域多个切片没有共同业务结果时，各自保留切片测试。测试进入更高层级后只保留一个权威文件，不得在相关切片中复制相同场景。

## 与生产构件共置

以下测试跟随被验证的明确生产构件，不参与业务跨度提升：

- 领域 `_shared/` 或全局 `shared/` 模块测试与对应模块共置。
- 公开契约测试与契约定义共置。
- 事件注册和依赖装配测试与组合根共置。
- 一个切片的公共入口即使使用其他领域的测试替身，测试仍与发起切片共置。

无真实基础设施的测试覆盖多个切片时，先寻找拥有该公共行为的切片；没有单一切片所有者且测试观察同领域共同结果时，提升到领域根；观察多个领域共同结果时，提升到 `features/` 根。

## 架构依赖检查

架构检查验证整个源码根的导入方向、禁止依赖、模块边界或循环依赖，不进入 `real_tests/`。按工具链支持选择距离被验证源码最近的位置：

1. 语言支持同文件或同包测试时，与源码直接共置。
2. 工具链使用配对测试源码集时，放在与生产源码集相邻的测试源码集中。
3. 配置式依赖检查规则放在被约束的源码根或构建清单附近。

一种项目只需采用工具链支持的实际形式，不为匹配示例同时创建多种架构检查位置。

## 真实环境测试

`real_tests/` 只接纳必须使用真实数据库、消息系统、文件服务、第三方服务、设备或完整部署环境的测试。此条件优先于业务跨度：同时跨领域并依赖真实环境的测试仍进入 `real_tests/`；轻量契约测试继续与生产适配器共置。

```text
<repository>/
└── real_tests/
    └── <capability-or-system>/
        ├── README.*
        ├── <test-scenarios>.*
        ├── <environment-definition>.*
        ├── <setup>.*
        ├── <seed-data>.*
        └── <cleanup>.*
```

真实环境测试按能力或目标系统分组；测试场景、环境定义、搭建、种子数据和清理文件位于同一组中。这些是职责占位符，只在真实需要时出现，不要求创建同名文件或空目录。

## 放置完成标准

测试位置仅在以下条件全部满足时合规：

- 文件位于它必须同时观察的最小公共边界。
- 切片、领域和跨领域场景按提升阶梯放置。
- 构件测试与对应生产构件共置。
- `real_tests/` 中的每个测试确实依赖真实环境，配套环境文件与场景按能力共置。
- 同一测试场景只有一个权威位置，没有跨层级重复。

# 测试归属规范

本文件只决定测试及其环境文件的位置。测试覆盖内容、真实环境授权、执行方式和清理成功条件由相应行为规范与工具链决定。具体文件名和测试源码集布局服从项目工具链；强制位置影响业务边界时读取 [`exceptions.md`](exceptions.md)。

## 放置流程

1. **识别边界：** 列出测试必须同时观察的公共结果、这些结果的生产所有者，以及是否必须连接真实基础设施；测试类型和最小公共边界均已明确时完成。
2. **架构检查：** 若测试验证导入方向、禁止依赖、模块边界或循环依赖，放在被约束源码最近且工具链可执行的位置；规则只有一个权威位置时完成。
3. **真实环境：** 若场景必须使用真实数据库、消息系统、文件服务、第三方服务、设备或完整部署环境，放入 `real_tests/<capability-or-system>/`；场景与所需环境文件已按能力共置时完成。
4. **构件共置：** 若测试验证 `_shared/`、`shared/`、公开契约、事件注册或依赖装配，与对应生产构件共置；测试位置能唯一指向被验证构件时完成。
5. **行为提升：** 其余测试沿“切片 → 领域 → `features/`”选择能容纳全部公共结果的最低层级；没有更小的单一行为所有者时才提升。
6. **消除重复：** 检查相关切片、领域根、`features/` 和 `real_tests/`；同一场景只保留一个权威位置时完成。

按以上顺序判断：架构检查、真实环境和明确生产构件先决定专属位置，普通业务场景再按业务跨度提升。导入模块数量、测试替身、代码长度或共享模块使用情况不改变归属。

## 业务跨度阶梯

```text
切片公共行为          → <source-root>/features/<domain>/<slice>/<test>.*
同领域跨切片业务场景  → <source-root>/features/<domain>/<test>.*
跨领域业务场景        → <source-root>/features/<test>.*
依赖真实环境的测试    → <repository>/real_tests/<capability-or-system>/
```

- 一个切片的公共入口即使使用其他领域的测试替身，测试仍归发起切片。
- 多个切片没有共同业务结果时，各自保留切片测试。
- 测试进入更高层级后，从原层级移除同一场景的副本。

## 构件与架构检查

- 领域 `_shared/`、全局 `shared/` 及公开契约的测试与定义共置。
- 事件注册和依赖装配测试与组合根共置。
- 架构检查优先采用同文件或同包测试；工具链使用配对源码集时，放在相邻测试源码集；配置式规则放在被约束源码根或构建清单附近。
- 每个项目只采用工具链实际支持的一种架构检查布局。

## 真实环境分组

```text
<repository>/real_tests/<capability-or-system>/
├── README.*
├── <test-scenarios>.*
├── <environment-definition>.*
├── <setup>.*
├── <seed-data>.*
└── <cleanup>.*
```

这些名称是职责占位符，只在场景真实需要时出现。业务跨度不覆盖真实环境优先级；无需真实基础设施的轻量契约测试继续与生产适配器共置。

## 完成标准

每个测试都位于它必须观察的最小公共边界，专属分支已按优先级处理，配套环境文件与场景共置，并且同一场景没有跨层级副本时，放置才完成。

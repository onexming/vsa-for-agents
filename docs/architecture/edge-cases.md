# 架构边界复合判断

本文件只处理单一专题流程无法唯一决定的三类复合边界。得出结论后，返回相应专题规范实施并验证。

## 跨领域相似校验

**触发：** 两个或多个领域出现形状相似的校验，无法直接判断应重复、共享还是建立公开能力。

1. UUID、邮箱语法、编码格式等纯技术校验，按 [`shared-code.md`](shared-code.md) 评估全局技术共享。
2. 最低订单金额、提现额度等领域规则由各自领域拥有；代码相似不改变所有权。
3. 业务语言确认规则属于同一更高层概念时，重新划分领域或建立公开能力。
4. 校验需要读取状态或产生副作用时，将其建模为行为，并按 [`feature-work.md`](feature-work.md) 或 [`cross-boundary-communication.md`](cross-boundary-communication.md) 处理。

**完成：** 规则所有者、业务含义和目标边界均唯一明确，结论不再依赖代码形状。

## 切片持续膨胀

**触发：** 出现以下至少两项，或任一项足以证明存在独立行为：

- 多种独立输入或触发入口；
- 可分别失败、重试或部署的子流程；
- 条件分支对应不同用户意图；
- 同时产生不相关结果；
- 测试自然分成互不相关的场景组；
- 修改一个分支持续影响无关分支。

按用户意图或业务结果划分候选切片。文件超过 6～8 个只触发审查；两个候选切片总是同步变化时，反向检查它们是否属于同一行为或当前领域边界是否错误。

**完成：** 每个结果切片都有单一意图、独立公共入口、可观察结果和完整行为测试；按 [`feature-work.md`](feature-work.md) 实施并验证。

## 高扇入领域共享

**触发：** 一个 `_shared/` 模块被五个以上切片引用，或持续增长并频繁牵动调用方。

1. 识别可保留的稳定模型、值对象、错误、事件和纯规则。
2. 找出副作用、流程编排、大量可选参数、场景标志及聚合的主动行为。
3. 将主动行为拆为切片；模块包含多个业务概念时重新划分领域。
4. 检查高扇入是否说明多个所谓切片其实属于同一更高层行为。

**完成：** 保留部分可独立理解、保持被动且不驱动任何切片；拆分或重新划界部分已按 [`shared-code.md`](shared-code.md) 与 [`feature-work.md`](feature-work.md) 验证。

# 架构例外规范

本文件是语言或平台固定目录、生成代码、遗留兼容及其他外部强制约束的授权流程。例外只隔离无法立即消除的约束，不改变常规业务边界，也不成为新代码模板。

## 处理流程

1. **证明约束：** 记录具体工具、接口、生成器或遗留依赖，以及常规合规方案为何不可行。存在可行方案时采用常规边界；客观约束和无可行替代均有证据时，例外才具备候选资格。
2. **限定范围：** 列出例外涉及的目录、组件、依赖和行为；范围已收敛到隔离约束所需的最小集合时完成。
3. **建立薄层：** 强制位置只负责输入转换和切片公共入口调用；业务契约、规则、状态变化与测试仍归功能切片。例外层不持有业务状态且没有业务分支时完成。
4. **查找决定：** 搜索已有 ADR；只有适用范围、约束和移除条件都覆盖当前情形时才沿用。匹配结果及理由已记录时完成。
5. **取得授权：** 没有有效 ADR 时，在采用例外前取得用户确认；授权明确覆盖当前范围时完成。
6. **记录迁移：** 复制 [`decisions/0000-template.md`](decisions/0000-template.md)，填写原因、范围、负责人、迁移目标、移除条件和复查日期；每项均具体且可检查时完成。
7. **验证隔离：** 从切片公共入口验证行为，运行相关测试和边界检查，并确认例外未扩散到新业务逻辑；验证全部通过时完成。

## 候选约束

只有以下情形进入上述流程：

- 语言、平台或框架强制目录结构。
- 代码生成器产生且不承载手写业务逻辑的代码。
- 为兼容遗留系统而保留的临时边界。
- 经用户确认、无法在当前变更中消除的其他外部约束。

开发便利、目录整齐、预计未来复用或避免建立公开协议不构成外部强制约束。

## 薄适配结构

```text
framework_routes/              # 强制位置：转换输入并调用公共入口
└── create_order.*

features/order/create_order/   # 权威业务切片
├── entry.*
├── implementation.*
└── test.*
```

框架目录只适配输入与输出；切片公共入口继续作为测试和协作边界。

## 停止点

仓库内可验证、可回退的重构直接恢复合规，不建立例外。若恢复合规需要破坏公开 API、迁移持久化数据、改变外部系统或新增生产依赖，按根 `AGENTS.md` 的授权闸门暂停，由用户选择批准变更或授权有移除条件的临时例外。

## 完成标准

每个例外都有用户授权或有效 ADR，记录覆盖范围、负责人、迁移目标、复查时间及可检查的移除条件；薄适配层未承载业务规则、状态或复用入口，且验证通过时，例外处理才完成。

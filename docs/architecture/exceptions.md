# 架构例外规范

本文件是处理语言或平台固定目录、生成代码、遗留兼容以及任何计划偏离架构规则时的唯一授权流程。例外不能成为新代码复制的模板。

## 可申请的情形

只有以下客观约束可以进入例外评估：

- 语言、平台或框架强制目录结构。
- 代码生成器产生且不承载手写业务逻辑的代码。
- 为兼容遗留系统而保留的临时边界。
- 经用户确认的其他不可在当前变更中消除的外部约束。

开发便利、目录整齐、预计未来复用或避免建立公开协议都不是例外理由。

## 处理流程

1. **证明约束：** 记录具体工具、接口或遗留依赖为何无法遵守常规边界；存在可行的合规方案时停止申请并采用该方案。
2. **建立薄适配层：** 把强制目录中的代码限制为输入转换和公共入口调用；业务契约、规则、状态变化与测试仍属于功能切片。
3. **搜索 ADR：** 只沿用适用范围、约束和移除条件均覆盖当前情形的已有记录。
4. **请求授权：** 没有有效 ADR 时，在采用例外前取得用户确认。
5. **记录决定：** 复制 [`decisions/0000-template.md`](decisions/0000-template.md)，写明原因、范围、负责人、迁移目标、移除条件和复查日期。
6. **验证隔离：** 例外没有扩散到新业务逻辑，依赖仍指向切片公共入口，相关测试和边界检查通过。

## 框架固定目录

```text
framework_routes/              # 框架强制位置，只转换输入并转发
└── create_order.*

features/order/create_order/   # 权威业务切片
├── entry.*
├── implementation.*
└── test.*
```

适配层不得实现业务规则、持有业务状态或成为其他切片的复用入口。切片公共入口仍是测试和协作边界。

## 自动重构的停止点

普通仓库内、可验证且可回退的重构应恢复合规，不建立例外。若恢复合规需要破坏公开 API、迁移持久化数据、改变外部系统或新增生产依赖，按根 `AGENTS.md` 的安全闸门暂停；用户可以选择批准变更或授权有移除条件的临时例外。

## 完成标准

每个现存例外都有用户授权或有效 ADR；记录包含明确范围、负责人、迁移目标和可检查的移除条件；例外外层保持薄适配，未成为新代码模板。
